400    /// How many Bluetooth bonds the device is holding
401    /// (`PROP_BLE_BOND_COUNT`)—`UINT8`, read-write. Requires `CAP_BLE`;
402    /// a device whose bonds it cannot manage answers
403    /// `STATUS_PROP_NOT_FOUND`.
404    ///
405    /// Writing 0 is how a host forgets every bond, along with the pairing
406    /// PIN and the failure lockout, leaving the device in pairing mode.
407    /// Zero is the only value a host may write: bonds are enrolled by the
408    /// pairing ceremony one at a time, so no other count is a state the
409    /// device could be put into, and the rest answer
410    /// `STATUS_INVALID_ARGUMENT`. The device answers once the deletion is
411    /// durable—over Bluetooth the last thing the sender hears, because
412    /// the bond carrying the answer is among those deleted.
413    ///
414    /// The count is live state rather than configuration, so it is not
415    /// part of the saved snapshot. It says how many hosts are enrolled,
416    /// never which: a bond identifies a host, and a device that named its

867/// Whether a property is writable by a mesh administrator.
868///
869/// Gates mutation only—`CMD_PROP_SET`/`INSERT`/`REMOVE`. Reads are
870/// never gated: an administrator may `CMD_PROP_GET` anything, and a
871/// property the device does not serve fails on its own terms.
872///
873/// The unwritable set is small and named explicitly by the spec rather
874/// than derived, because "device domain" is not a property of the key: a
875/// host-domain table and a device-domain one differ only by which half of
876/// the device they configure. A device answers writes to all of these with
877/// `STATUS_NOT_PERMITTED`—the property exists, and the binding is what
878/// refused it.
879pub fn admin_writable(key: u32) -> bool {
880    !matches!(
881        key,
882        // The host domain in full: the assistance the device owes to
883        // whatever host it serves is that host's business.
884        prop::HOST_KEY
885            | prop::HOST_CHANNEL_KEYS
886            | prop::HOST_PEER_KEYS
887            | prop::HOST_RX_FILTERS
888            | prop::HOST_AUTO_ACK
889            | prop::HOST_RX_QUEUE_COUNT
890            | prop::HOST_RX_QUEUE_CAPACITY
891            | prop::HOST_RX_QUEUE_DROPPED
892            | prop::HOST_MUTED_CHANNELS
893            | prop::HOST_MUTED_PEERS
894            // Session state: an exchange is not an attach, so there is no
895            // session for it to configure. `PROP_MAC_BACKHAUL` is the
896            // exception: which side of the radio multiplexer the tethered
897            // host sits on is worth flipping from across the mesh, so an
898            // administrator may write it even though the host's next
899            // attach resets it.
900            | prop::MAC_PROMISCUOUS
901            // A device identity cannot be installed over the mesh.
902            | prop::DEV_PRIVATE_KEY
903    )
904}
