pub fn rx_busy_window_ms(mdltn: &ModulationParams, sender_preamble: u16) -> u32
Expand description

How long a detected preamble keeps the channel busy, in milliseconds.

The on-air time of a maximum-length frame measured from the start of its preamble: sender_preamble symbols (at least RX_BUSY_PREAMBLE_SYMBOLS), sync word, header, and a MAX_PAYLOAD-byte payload at the receiver’s spreading factor, bandwidth, and coding rate. The chip raises its preamble IRQ somewhere inside the preamble (or, for a valid header, later still), so any frame that IRQ belongs to has ended by the time this window has elapsed from it.

Explicit header and CRC are assumed, as the runners configure them; both only lengthen a frame, so the bound also covers a sender without them. Low-data-rate optimization is assumed for every symbol longer than 16 ms, a superset of each supported chip’s own rule. The coding rate is the receiver’s: an explicit header would let a sender pick a slower one, but every profile fixes it.
