Crate umsh_communicator 

Source
Expand description

A communicator’s durable chat state.

  • ChatStore: what a back end keeps—chats, messages, the resend archive, outbound checkpoints, peers, and channels—and the order it commits them in.
  • Batch: one commit’s worth of the text engine’s outputs, in the order the store writes them.
  • MemoryStore: the store worked on in memory, alone for tests, or over a Durable layer that keeps its records.
  • FlashMapStore (feature flash): the store kept in a sequential-storage map on flash.
  • conformance: the suite every back end passes, power cut between each step of the commit order included.
  • CommunicatorNode (feature node): the node behind the interface, with the device’s settings reached through its own ULCP session and its chats fed by the device node through task.

Device settings and security state are not stored here: the device keeps the first, and the second stays with the MAC.
