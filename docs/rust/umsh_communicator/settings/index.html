Module settings 

Source
Expand description

The device’s settings, as the communicator shows and changes them.

Every setting is a property of the device’s own ULCP session, reached through a [LocalExchange]. A change is a request the session serves as it serves any host’s, and what the session publishes keeps the cache current, whoever made the change: this interface, an attached phone, or an administrator across the mesh.

A setter changes what its read reports at once. The outcome follows as an event: [NodeEvent::SettingsChanged] once the device has applied it, or [NodeEvent::SettingRefused], after which the read reports what the device kept.

Saving. The device keeps an existing snapshot in step with every change made here (ulcp-saved-state.md, Changes Made at the Device), but never makes one. So the first boot saves one, and a change whose loss would matter—the name, the radio—is followed by a save when the device has none in effect. Brightness and the keyboard never ask for one.

Peers and channels. The device’s store keeps PROP_DEV_PEERS and PROP_DEV_CHANNEL_KEYS outside the snapshot, so changing them asks for no save. A communicator starts out on public and EMERGENCY: they are what its channel keys hold after a reset (ulcp-device.md, Lists Held by the Device’s Store; see ChannelCrypto::starting_keys).
