Simulated ULCP device: the production device [Session] behind a deterministic in-memory link.

The storage, radio, RSSI sampler, and entropy source are small stand-ins; every protocol decision is made by the real session. What stands where a radio would is a queue: transmissions accumulate until SimulatedDevice::take_transmitted drains them, so the caller decides what “the air” is — the web debugger discards it, a bridge copies it to real segments.

The SessionConfig is the caller’s: it names the device and declares its capability surface. A simulated device has no node behind it, so its configuration must leave SessionConfig::mac_node unset — Effect::ApplyBackhaul would connect the host to nothing.
