The chat transmit queue.

Frames go to the node through a bounded window, so a message larger than the window waits here rather than in the MAC’s own queue. A frame leaves the window when nothing more can happen to it: acknowledged or failed, or transmitted when no acknowledgment will follow.

Hand waiting frames to the node while the window has room. Returns how many were sent: each is an authenticated send that advanced the frame counter. It is TransmitQueue::depart, transmit, and TransmitQueue::departed in a loop, for a caller that holds the facade across the sends.

Source

pub fn depart( &mut self, channels: &ChannelRegistry, policy: &TransmitPolicy, ) -> Option<Result<Departure, Undeliverable>>

The next frame the window has room for, with where it goes resolved against channels. None when nothing may leave now.

  • A unicast asks for an acknowledgment, and a peer gets one frame in flight until its first is acknowledged: first contact may need counter synchronization. Until then it names us by full key, since a peer that has not registered us cannot read a frame that names us by hint.
  • A channel multicast carries the full source key, so a member who misses a fragment can address a resend request to us.
  • A channel-direct frame is a blind unicast, registering the peer on the way out.
  • EMERGENCY goes out unencrypted, so any node in range can read it.

A frame on a channel no longer held comes back undeliverable.
