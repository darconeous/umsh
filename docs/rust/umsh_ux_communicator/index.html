The standalone messenger interface for communicator-class UMSH devices.

A communicator provides the whole UMSH experience on the device: it has a color screen, a text keyboard, and navigation controls, and a phone is optional. The T-LoRa Pager is the first target; its mockup in docs/ux/src/hardware/mockups/ is the reference design.

  • model: what the screens show, filled in by the device.
  • ui: the screens themselves, as Buoyant views.
  • input: the inputs a board reports, and what they mean.
  • avatar: peer and channel avatars, following the iOS rules.
  • font, icon, theme: typefaces, icons, colors, and sizes.
  • fixture: stand-in content (the fixture feature).

[buoyant] is re-exported so a device drives the interface with the same version it was built against.

Modules§

avatar
Avatars: the colors, lettering, and outline that identify a peer or a channel at a glance.
fixture
Stand-in content until a real node backs the interface: the chats from the T-LoRa Pager mockup, so a render compares directly with it.
font
The bundled typefaces: M PLUS 1 for text and M PLUS Code Latin for addresses, each at the weights and pixel sizes the screens use.
icon
Interface icons, rasterized at build time from the mockup’s glyphs and drawn as templates in the foreground color.
input
Input as the interface understands it, independent of how a board produces it.
model
What the screens show: plain data the device fills in from its node, chat store, and peripherals, kept separate from how it is drawn.
theme
Colors and type sizes shared by every screen.
ui
The screens, as Buoyant views over State.
