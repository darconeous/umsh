Module model 

Source
Expand description

A cached model of one device’s settings.

The model is a reducer. Its owner makes requests—reads, writes, saves—which wait in a queue, and calls Model::pump to hand them to an Exchange and take in whatever has come back. Nothing it does waits for an answer: a write stays pending until its answer arrives, and the cache keeps showing what the device last reported until then.

  • Reads made one after another go out together, as one CMD_PROP_MULTI_GET. A device that runs out of room in its reply answers the first part, and the model asks for the rest.
  • Writes go out in the order they were made, each as its own request. The answer is the value the device applied, a value it adjusted the write to, or the status it refused it with.
  • Publications keep the cache current between reads. A device that resets, or a link that dropped publications, leaves every value stale, and the model reads them all again.
