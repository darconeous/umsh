This UEP defines the node identity: what a node says about itself, how that
statement is encoded and signed, the advertisements that announce it, and the
Identity Request command that asks a node for it.

## Identity Payload {#payload}

A node identity is a payload of [payload type](uep-0005.md#payload) 1:

```text
+--------------+------+------+---------+------+-----------+
| PAYLOAD TYPE | ROLE | CAPS | OPTIONS | 0xFF | SIGNATURE |
+--------------+------+------+---------+------+-----------+
      1 B        1 B    1 B   variable   1 B     64 B
```

- `ROLE`: the node's [role](#roles).
- `CAPS`: the node's [capabilities](#capabilities).
- `OPTIONS`: an [options block](uep-0003.md#options) of
  [identity options](#identity-options), which may be empty.
- `0xFF`: the [end marker](uep-0003.md#end-marker), present only when a
  signature follows.
- `SIGNATURE`: an optional [signature](#signatures).

The smallest identity is `ROLE` and `CAPS` alone. Any packet type that carries
a payload may carry an identity.

A receiver discards an identity that is shorter than two bytes, whose options
block is [malformed](uep-0003.md#malformed), or whose bytes after the end
marker are neither absent nor exactly 64.

## Roles {#roles}

`ROLE` names what the node is for:

| Value | Role |
|---:|---|
| 0 | Unspecified |
| 1 | Repeater |
| 2 | Chat |
| 3 | Tracker |
| 4 | Sensor |
| 5 | Bridge |
| 6 | Chat Room |
| 7 | Temporary Session |

A receiver treats a role it does not recognize as Unspecified.

## Capabilities {#capabilities}

`CAPS` is a bitmap of what the node does, independent of its role:

```text
  7   6   5   4   3   2   1   0
+---+---+---+---+---+---+---+---+
| - | - |CoA|CHR|TLM|TXT|MOB|REP|
+---+---+---+---+---+---+---+---+
```

| Bit | Name | Meaning |
|---:|---|---|
| 0 | `REP` | A repeater its neighbors can plan on |
| 1 | `MOB` | Mobile or handheld, rather than fixed |
| 2 | `TXT` | Receives [text messages](uep-0020.md) |
| 3 | `TLM` | Provides public telemetry |
| 4 | `CHR` | Hosts a chat room |
| 5 | `CoA` | Serves CoAP |

A sender clears bits it does not define, and a receiver ignores them. A node
with the Chat role that also repeats sets `REP`. A node that forwards only
where nobody else is heard to, an [adaptive forwarder](uep-0018.md#identity),
does not.

## Identity Options {#identity-options}

| Number | Name | Value |
|---:|---|---|
| 0 | [Name](#name) | UTF-8 string, at most 24 bytes |
| 1 | [Location](#location) | 1 to 7 bytes |
| 2 | [Altitude](#altitude) | Signed integer, at most 4 bytes |
| 3 | [Timestamp](#timestamp) | Unsigned integer, at most 4 bytes |
| 5 | [Nonce](#nonce) | 4 bytes |

Option 4, Supported Regions, is defined in
[UEP-0014](uep-0014.md). A receiver ignores an option it does not recognize.
Each option appears at most once unless its definition says otherwise, and a
receiver uses the first of any repeats.

A receiver ignores an option whose value it cannot use: one longer than the
option's limit, or a Location of no bytes. A Nonce whose value is not 4 bytes
is the exception: a receiver discards the whole identity, as
[Signature Domain](#signature-domain) relies on. A Name that is not valid
UTF-8 is displayed as [UEP-0003](uep-0003.md#strings) defines.

An integer value is big-endian and **minimal**: a sender omits every leading
byte that the value does not need, so zero has an empty value. An unsigned
value omits leading `0x00` bytes. A signed value is two's complement and omits
each leading `0x00` or `0xFF` byte whose removal leaves the sign bit of the
remaining value unchanged. A receiver accepts a value that is not minimal.

### Name (0) {#name}

The node's display name. A sender that shortens a longer name cuts it as
[UEP-0003](uep-0003.md#strings) defines.

### Location (1) {#location}

The node's position, as a [location code](uep-0010.md#format) of 1 to 7 bytes.
A sender MUST NOT send more than 7 bytes, and a receiver ignores bytes past
the seventh.

### Altitude (2) {#altitude}

The node's altitude in meters above mean sea level, as a minimal signed
integer.

### Timestamp (3) {#timestamp}

When the identity was generated, in seconds since the Unix epoch (UTC), as a
minimal unsigned integer. It lets a receiver judge how fresh an identity is,
which matters most for one that stands alone, such as in a QR code.

### Nonce (5) {#nonce}

The `NONCE` of the [Identity Request](#identity-request) that this identity
answers, copied unchanged. Present only in a response to a request that
carried one.

## Signatures {#signatures}

An identity's embedded signature lets it stand apart from any frame, as in a
QR code or an exported contact. It is an Ed25519 signature by the node's
key over the payload from `ROLE` through the `0xFF` end marker, inclusive,
not including the payload type. A receiver verifies it against the address
of the node the identity describes, with the cofactorless equation and the
rejections that
[UEP-0007 §signature-verification](uep-0007.md#signature-verification)
requires of a frame signature.

An identity carried in a frame is authenticated by that frame, and need not
be signed. A receiver believes an identity only when:

- its embedded signature verifies, or
- it has no embedded signature, and its frame authenticates the sender: a
  verified [frame signature](uep-0007.md#frame-signatures), or a unicast or
  group unicast MIC.

A multicast MIC does not authenticate the sender, since any member of the
group can send under any source address. An identity whose embedded
signature does not verify is not believed.

An identity authenticated by its frame SHOULD replace the details a receiver
holds only when that frame advanced the sender's established
[baseline](uep-0007.md#replay-detection). A frame accepted as first contact,
or from behind the baseline, MAY fill missing details but SHOULD NOT replace
held ones, since a late frame can carry older details. A baseline restored
from storage is established.

An identity believed only on its embedded signature SHOULD NOT replace held
details unless it carries a Timestamp later than that of the details held.
Anyone can put a captured identity back on the air.

## Advertisements {#advertisements}

An **advertisement** is a broadcast or multicast whose payload is its
sender's node identity, sent unprompted to announce the node's presence,
name, role, and capabilities.

- An advertisement carries a
  [frame signature](uep-0007.md#frame-signatures), which authenticates the
  identity it carries, so the identity need not also be signed.
- A receiver can check a frame signature only against an address it holds or
  the packet carries. An advertisement meant for receivers that may not hold
  its sender's address MUST carry that address in full in `SRC`
  ([UEP-0005](uep-0005.md#source-address)).
- A node SHOULD send a scheduled advertisement without
  [`FHOPS`](uep-0005.md#fhops). It restates a standing identity rather than
  news, so flooding it on every period spends airtime out of proportion to
  what a distant listener learns. A node that wants to be reachable from
  farther away publishes a path with a beacon instead
  ([UEP-0016](uep-0016.md#beacons)).

### Announcing on a Schedule {#announcing}

A node MAY send advertisements on a period of its own. The period is a floor
on how often the node advertises unprompted, not an exact cadence: a node
SHOULD delay each advertisement by a random fraction of the period, such as
up to a quarter of it, and MUST NOT send one sooner than the period allows.
Nodes started together would otherwise stay in step, and collide on every
period.

## Identity Request (1) {#identity-request}

Asks the destination for its node identity. It is a
[MAC command](uep-0006.md#encoding) whose fields are an options block:

| Field | Size | Description |
|---|---:|---|
| Request options | 0+ bytes | An [options block](uep-0003.md#options) of [request options](#identity-request-options) |

A responder answers with a node identity carried by unicast or group unicast.
A response is not signed, and carries the request's `NONCE` in its
[Nonce option](#nonce).

### Request Options {#identity-request-options}

| Key | Name | Value | Description |
|---:|---|---|---|
| 1 | `NONCE` | 4 bytes | Copied into the response. Not a filter |
| 3 | `FILTER_NODE_HINT` | 1–3 bytes | Selects a node whose [node hint](uep-0004.md#node-hint) begins with this value |
| 5 | `FILTER_NODE_ROLE` | 1 byte | Selects a node whose role is this value |
| 7 | `FILTER_NODE_CAPS` | 1 byte | Selects a node whose capabilities include every bit set in this value |

A filter value of any other length selects nothing. An odd key is critical
and an even key elective. A node that meets a critical
key it does not recognize is not selected, and does not answer.

A node is selected when it satisfies every filter type the request carries.
It satisfies a filter type when it matches any one of that type's values. A
request with no filters selects every node.

A requester that knows a node's whole hint sends all three bytes. The two-byte
[repeater hint](uep-0004.md#repeater-hint) is the most a path reveals of the
repeaters along it.

### Carriage {#identity-request-carriage}

An Identity Request may be carried by any packet type that carries a payload.
A request carried by multicast or broadcast is a **solicitation**, and MUST
carry at least one filter. A solicitation SHOULD carry the requester's full
address in `SRC` unless every node it selects is known to hold it. A node
that cannot resolve the requester's address does not answer.

The response to a unicast or group unicast request is carried as
[UEP-0005 §response-carriage](uep-0005.md#response-carriage) defines. The
response to a solicitation is a unicast to its requester. A response SHOULD
carry the responder's full address in `SRC`
([UEP-0005](uep-0005.md#source-address)) unless the requester is known to
hold it.

### Solicitations {#solicitations}

A solicitation can draw an answer from every node it reaches. A node that
answers one:

1. **Delays its answer** by a random time drawn uniformly from 0.5 to 30
   seconds, so the nodes it selected do not answer at once. A solicitation
   whose only hint filter is one `FILTER_NODE_HINT` of 2 or 3 bytes names one
   node, and MUST be answered without the delay.
2. **Answers once.** A node suppresses a solicitation from the same sender
   with the same `NONCE` as one it has answered, for at least as long as it
   may hold the answer. A solicitation without a `NONCE` cannot be told from a
   repeat of itself, so a requester that wants a further answer sends a new
   `NONCE`.
3. **Stays local unless named.** A solicitation with no `FILTER_NODE_HINT`, or
   with more than one, names as many nodes as it reaches or as it has
   filters, so it is confined to the requester's neighbors. A node MUST NOT
   answer one that carries [`FHOPS`](uep-0005.md#fhops) with either count
   nonzero, and its answer MUST NOT carry `FHOPS`. A solicitation with
   exactly one `FILTER_NODE_HINT` may travel as far as its flood hop count
   allows.

A node MAY relax the first and third rules for solicitations on a
[simple private group](uep-0008.md#simple-private-groups). It MUST NOT relax
them for a broadcast or for a [named group](uep-0008.md#named-groups).

A node MAY decline any request from a node it does not know. A node SHOULD
bound the rate at which it answers requests whose frame does not authenticate
the sender, and leave requests over the bound unanswered. Such a request's
source is only a claim, and the answer goes to the node it names.

A solicitation is answered by unicast, never by an
[advertisement](#advertisements).

## Registry Considerations {#registry-considerations}

This UEP creates the [Node Roles](registries/node-roles.md),
[Capability Bits](registries/capability-bits.md),
[Identity Options](registries/identity-options.md), and
[Identity Request Options](registries/identity-request-options.md)
registries.

- **Node Roles**: values 0 to 255, allocated by a standards UEP. The registry
  reserves no experimental values.
- **Capability Bits**: bits 0 to 7, allocated by a standards UEP. The
  registry reserves no experimental values.
- **Identity Options**: values 0 to 65535, allocated by a standards UEP.
  Values from 60000 up are
  [experimental](uep-0001.md#experimental-values).
- **Identity Request Options**: values 0 to 65535, allocated by a standards
  UEP. An odd value is critical and an even one elective. Values from 60000
  up are experimental.

This UEP allocates roles 0 to 7, capability bits 0 to 5, identity options
0, 1, 2, 3, and 5, and request options 1, 3, 5, and 7, as defined above. In
the [MAC Commands](registries/mac-commands.md) registry it allocates:

| Value | Command | Defined in |
|---:|---|---|
| 1 | Identity Request | [UEP-0011](#identity-request) |

## Security Considerations {#security-considerations}

### Claims {#claims}

An identity is its node's own statement. A verified signature or an
authenticated frame shows which node made the statement, not that the
statement is true: a node may claim any role, capability, name, or position.

Believing an identity is not evidence that its node is in range. An embedded
signature carries no freshness, so a captured identity verifies wherever and
whenever it is put back on the air. The Timestamp option bounds how stale a
standalone identity can claim to be, but only to a receiver that knows the
time.

### Signature Domain {#signature-domain}

The embedded signature covers the identity's bytes with no domain prefix. A
frame signature's input begins with `"UMSH-SIG"`, whose first two bytes are
role 85 and capabilities `0x4D`. The bytes after them, `53 48 2D …`, begin
an option 5 record with a 3-byte value, and a receiver discards an identity
whose Nonce is not 4 bytes. So no frame signature input parses as an
identity, and a frame signature cannot pass for an identity signature.

### Solicitations {#solicitation-security}

A solicitation is a request carried by multicast or broadcast, which
[UEP-0008](uep-0008.md#security-considerations) warns about. The rules of
[Solicitations](#solicitations) bound what one can draw: the delay spreads
the answers, the `NONCE` keeps a request that arrives by several paths from
being answered more than once, and the hop rule keeps a request that names
many nodes from drawing answers across the mesh.

A broadcast request authenticates nothing, so its source is whatever the
requester claims. A node that answered every one would send a unicast to any
node an attacker named. The rate bound on answers to unauthenticated
requests limits that.

### Location {#location-security}

A Location option discloses where a node is, as
[UEP-0010](uep-0010.md#security-considerations) describes. It states only
what the identity claims. Nodes within radio range can locate a transmitter
by which nodes hear it and how strongly, whatever its identity says.
