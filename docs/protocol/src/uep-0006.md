This UEP defines MAC commands: short requests and responses that nodes
exchange to manage the link between them. It defines how a command is
encoded and carried, and the Echo and No-Op commands. Other commands are
defined in the UEPs for the features they serve.

## Command Encoding {#encoding}

A MAC command is a payload of [payload type](uep-0005.md#payload) 2:

```text
+--------------+------------+----------------+
| PAYLOAD TYPE | COMMAND ID | COMMAND FIELDS |
+--------------+------------+----------------+
      1 B           1 B         variable
```

- `COMMAND ID`: one byte naming the command. Values 0 to 127 identify
  commands. Values 128 to 255 are reserved, and a receiver ignores a command
  that carries one.
- `COMMAND FIELDS`: the fields the command defines, which may be none.

A receiver reads the fields a command defines and ignores any bytes after
them. It ignores a command shorter than its defined fields, and a command it
does not implement. A node implements any subset of the commands.

## Carriage {#carriage}

A MAC command is carried by [unicast](uep-0005.md#unicast) or
[group unicast](uep-0005.md#group-unicast). A command whose definition
permits it may also be carried by multicast or broadcast. A node ignores any
other command that arrives by multicast or broadcast.

A response to a command is carried as
[UEP-0005 §response-carriage](uep-0005.md#response-carriage) defines.

## Echo {#echo}

### Echo Request (4) {#echo-request}

Asks the destination to answer with an [Echo Response](#echo-response).
Carried by unicast and group unicast only.

| Field | Size | Description |
|---|---:|---|
| Echo data | 0+ bytes | Chosen by the sender |

An echo measures round-trip latency and tests reachability. Its response
also carries the destination's current frame counter, which
[UEP-0007](uep-0007.md) uses to resynchronize counters.

### Echo Response (5) {#echo-response}

Answers an Echo Request. Carried by unicast and group unicast only.

| Field | Size | Description |
|---|---:|---|
| Echo data | 0+ bytes | Copied from the Echo Request |

A node that implements Echo Request answers each one it accepts with an Echo
Response. The response SHOULD use the MIC size the request used.

## No-Op (9) {#no-op}

Asks nothing of the destination. The destination acknowledges it as it does
any packet that requests an acknowledgment, and does nothing else. Carried by unicast and group unicast only.

Sent in a packet that requests an acknowledgment, No-Op tests reachability
and measures round-trip latency: the MAC ack is the answer. It works with any
destination, since acknowledging a packet does not depend on implementing the
command it carries.

No-Op defines no fields. A sender MAY follow the command identifier with
filler, to give the packet the size it wants to test.

## Registry Considerations {#registry-considerations}

This UEP creates the [MAC Commands](registries/mac-commands.md) registry.

Values 0 to 127, allocated by a standards UEP whose definition states whether
the command may be carried by multicast or broadcast. Values 128 to 255 are
reserved. The registry reserves no experimental values.

This UEP allocates:

| Value | Command | Defined in |
|---:|---|---|
| 4 | Echo Request | [UEP-0006](#echo-request) |
| 5 | Echo Response | [UEP-0006](#echo-response) |
| 9 | No-Op | [UEP-0006](#no-op) |

## Security Considerations {#security-considerations}

A MAC command is as authentic as the packet that carries it. By unicast or
group unicast, it comes from the holder of the source's key. By multicast, it
comes from some member of the group. By broadcast, nothing authenticates it
unless the broadcast carries a frame signature. A UEP that permits a command
by multicast or broadcast accounts for this.

An Echo Response is as large as its request, so Echo amplifies nothing, but
every request a node answers costs the network a second packet. A node MAY
limit how often it answers.
