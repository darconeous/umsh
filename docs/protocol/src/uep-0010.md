This UEP defines the location code: a compact, hierarchical encoding of a
position on the globe, whose length sets its precision. It also defines how
a sender can dilute a location it reports.

## Format {#format}

A location code is one or more bytes. Each byte divides its parent cell into a
16 × 16 grid and selects one cell of it, with the high nibble indexing
latitude and the low nibble longitude:

```text
  7   6   5   4   3   2   1   0
+---------------+---------------+
|  LAT NIBBLE   |  LON NIBBLE   |
+---------------+---------------+
```

The first byte divides the whole globe, so that each of its cells spans 11.25°
of latitude and 22.5° of longitude. Each further byte divides the cell the
bytes before it select.

## Encoding {#encoding}

A position at latitude `LAT` (−90 to +90) and longitude `LON` (−180 to +180),
in degrees, encodes to `N` bytes through two indices:

```text
lat_index = floor((LAT +  90) × 16^N / 180)
lon_index = floor((LON + 180) × 16^N / 360)
```

Each index is clamped to `16^N − 1`, so `LAT = +90` and `LON = +180` fall in
the last cell. Byte `k`, counting from 0, is then:

```text
high nibble = (lat_index >> (4 × (N − 1 − k))) & 0xF
low nibble  = (lon_index >> (4 × (N − 1 − k))) & 0xF
```

Truncating an `N`-byte code to `k` bytes yields the `k`-byte code for the same
position, so a sender coarsens a location by dropping bytes. An
implementation that computes the code otherwise, such as one byte at a time,
MUST produce the same bytes.

## Decoding {#decoding}

A code denotes the whole cell it selects. A receiver that needs a single point
uses the center of the cell.

## Precision {#precision}

| Bytes | Latitude cell | Longitude cell | Cell at the equator |
|---:|---|---|---|
| 1 | 11.25° | 22.5° | 1,250 × 2,500 km |
| 2 | 0.703125° | 1.40625° | 78 × 156 km |
| 3 | 0.0439° | 0.0879° | 4.9 × 9.8 km |
| 4 | 0.00275° | 0.00549° | 305 × 610 m |
| 5 | 0.000172° | 0.000343° | 19 × 38 m |
| 6 | 1.07 × 10⁻⁵° | 2.15 × 10⁻⁵° | 1.2 × 2.4 m |
| 7 | 6.71 × 10⁻⁷° | 1.34 × 10⁻⁶° | 7.5 × 15 cm |

A cell's east–west extent narrows away from the equator, so a given number of
bytes discloses a smaller area at high latitudes.

Codes that share a prefix select nearby cells, but nearby positions on
either side of a cell boundary may share no prefix. A comparison of prefixes
suits only coarse filtering, and a proximity query also checks the
neighboring cells.

## Diluted Locations {#diluted-locations}

A sender MAY offset its position before encoding it, so that the cell it
reports is not aligned to where it is. A receiver cannot tell a diluted
location from a true one.

A sender that dilutes its location MUST NOT draw a new offset for each
report. Fresh noise on each report, quantized to a cell, lets an observer who
averages reports recover the position more precisely than the cell, without
bound as reports accumulate.

A construction that avoids this:

- Draw the offset uniformly over a disk or box, in meters, and convert it to
  degrees at the current latitude. A peaked distribution, such as a Gaussian,
  still makes the reported position the most probable true one.
- Size the offset between about half and twice the extent of the coarsest cell
  being protected.
- Derive the offset from a keyed hash of a secret key and the position
  quantized to a coarse cell, so the same place always yields the same
  offset. Keep the current offset until the position has moved well into a
  neighboring cell, so that a node on a boundary does not alternate between
  two.
- Apply the offset once, and derive every precision the node publishes by
  truncating the one diluted position.

A held offset protects a stationary position. The track of a moving node is
its true track displaced by a constant, and its shape against roads or
coastlines can reveal the offset. Any one correlation of a report with the
true position reveals the offset for as long as it is held.

## Security Considerations {#security-considerations}

A location discloses where a node is, to the precision its sender chooses.
A cell is a set, and an observer with context can narrow it: a cell that is
mostly water, with land at one edge, reports that edge. Truncation alone
cannot defend against such knowledge, since the cell is always aligned to the
fixed grid. A [diluted location](#diluted-locations) can.
