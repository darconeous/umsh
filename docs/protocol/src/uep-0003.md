This UEP defines the requirement language, terminology, and common encodings
that other UEPs build on.

## Requirement Language {#requirements}

The key words **MUST**, **MUST NOT**, **REQUIRED**, **SHALL**, **SHALL NOT**,
**SHOULD**, **SHOULD NOT**, **RECOMMENDED**, **NOT RECOMMENDED**, **MAY**, and
**OPTIONAL** are to be interpreted as described in
[RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) and
[RFC 8174](https://www.rfc-editor.org/rfc/rfc8174) when,
and only when, they appear in all capitals.

A limit that a UEP places on the wire—the size of a field, the number of
times something may appear, the range of a value—is a requirement on the
sender, stated as what the sender MUST NOT do. A receiver that meets a value
outside such a limit discards the item that carries it, and counts the
discard where it keeps statistics.

## Terminology {#terminology}

These terms are used across UEPs. A term that belongs to one feature is
defined in the UEP for that feature.

**Node**
: A logical participant in a UMSH network, identified by an Ed25519 keypair.
  One physical device may host several nodes.

**Address**
: A node's 32-byte Ed25519 public key, which serves as both its network
  identifier and its credential.

**Hint**
: A short prefix of an address, carried on the wire in place of the full
  address.

**Packet**
: The unit of the UMSH protocol. Every packet fits in a single frame.

**Frame**
: One transmission on the physical medium. *Frame* and *packet* name the same
  thing: *frame* emphasizes the transmission, *packet* the protocol unit.

**Payload**
: The content a packet carries for the protocol above the MAC layer.

**Hop**
: One leg of a packet's path: a transmission from one node to a node within
  its radio range. A direct neighbor is one hop away, and a packet relayed by
  two repeaters travels three hops. A packet a node addresses to itself is
  never transmitted and crosses zero hops.

**Repeater**
: A node that forwards packets on behalf of other nodes.

**Unicast**
: A packet addressed to a single node.

**Multicast**
: A packet addressed to the members of a group.

**Broadcast**
: A packet addressed to every node that receives it.

**Group**
: A set of nodes that share a symmetric group key. A group carries multicast
  traffic and conceals the addresses of blind unicast.

**Blind Unicast**
: A unicast packet whose source and destination addresses are concealed from
  nodes outside a group.

**MIC**
: Message integrity code: the authentication tag carried by an authenticated
  packet. UMSH says MIC rather than MAC to avoid confusion with the medium
  access control layer.

**MAC Layer**
: The layer that frames, addresses, secures, and forwards packets, treating
  their payloads as opaque.

**PHY**
: The physical layer, which modulates and transmits frames on the medium.

**Device**
: Hardware that owns a radio and runs always-on firmware.

**Host**
: A computer, such as a phone, that controls a device over a local link.

**RSSI**
: Received signal strength indicator: received signal power, in dBm.

**SNR**
: Signal-to-noise ratio: received signal power relative to the noise floor,
  in dB. Under LoRa it stays meaningful below the noise floor, where RSSI
  does not.

## Byte Order {#byte-order}

Multi-byte numeric fields are big-endian: most significant byte first.
[Packed unsigned integers](#pui) are the exception.

Hashes, keys, and signatures are carried in their canonical byte form, without
regard to the byte order of any value they represent.

## Packed Unsigned Integers {#pui}

A **packed unsigned integer** encodes a value from 0 to 2,097,151 in one to
three bytes, so that small values take one byte without limiting how large a
value can grow. The encoding is the unsigned integer encoding of
[EXI](https://www.w3.org/TR/exi/#encodingUnsignedInteger), limited to three
bytes:

1. Split the value into 7-bit groups, using the fewest groups that hold it.
2. Place the groups one per byte, least significant group first.
3. Set the high bit of every byte but the last.

A value from 0 to 127 is therefore a single byte holding the value. A decoder
reads bytes until it reaches one whose high bit is clear, and the encoding is
malformed if the third byte's high bit is set or the data ends first.

A sender MUST NOT use more bytes than the value needs. A decoder reads a
longer encoding as the value it encodes.

## Option Encoding {#options}

An **options block** carries a set of numbered fields compactly, using the
delta-length encoding of CoAP
([RFC 7252, Section 3.1](https://www.rfc-editor.org/rfc/rfc7252#section-3.1)). Each field is an
**option record**: an option number, a length, and a value.

### Option Records {#option-records}

A record begins with a byte holding two 4-bit fields, followed by up to two
extended delta bytes, up to two extended length bytes, and the value:

```text
  7   6   5   4   3   2   1   0
+---------------+---------------+
| Option Delta  | Option Length |  (1 byte)
+---------------+---------------+
| Extended Delta (0–2 bytes)    |
+-------------------------------+
| Extended Length (0–2 bytes)   |
+-------------------------------+
| Option Value (0 or more bytes)|
+-------------------------------+
```

Each nibble is read as follows:

| Nibble | Meaning |
|---:|---|
| 0–12 | The value itself |
| 13 | One extended byte follows; the value is that byte plus 13 |
| 14 | Two extended bytes follow; the value is that big-endian 16-bit integer plus 269 |
| 15 | Reserved for the [end marker](#end-marker) |

The delta is the record's option number minus the previous record's option
number, or the option number itself for the first record. Records appear in
order of increasing option number. An option number may repeat, with a delta
of zero.

Option numbers range from 0 to 65535.

### End Marker {#end-marker}

An options block may be followed by data. When it is, the byte `0xFF`—a delta
nibble and a length nibble both of 15—separates the block from the data. A
`0xFF` with nothing after it marks empty data.

A sender omits `0xFF` when no data follows. A receiver accepts `0xFF` wherever
a record could begin, including when nothing follows it.

The format that contains an options block determines where the block and any
data after it end.

### Malformed Blocks {#malformed}

An options block is malformed if:

- a nibble of 15 appears anywhere other than in the end marker
- the option numbers it names exceed 65535
- a record's extended bytes or value run past the end of the block

A UEP that uses this encoding states what a receiver does with a malformed
block.

## Strings {#strings}

Human-readable text is UTF-8
([RFC 3629](https://www.rfc-editor.org/rfc/rfc3629)). A string's length
comes from its context: an option record's length, or the end of the data
that contains it.

A string carried whole MUST be valid UTF-8. A sender that shortens a string
to fit a byte limit therefore cuts it at a character boundary, and MAY cut it
at an extended grapheme cluster boundary
([Unicode Standard Annex #29](https://www.unicode.org/reports/tr29/)), so
that an emoji sequence or a letter with combining marks is kept or omitted
whole.

A UEP may carry one string in several pieces, split at arbitrary byte
boundaries. A piece may then end partway through a UTF-8 sequence or a
grapheme cluster, and only the joined string MUST be valid UTF-8. A receiver
MUST join the pieces before decoding them.

A receiver given a string that is not valid UTF-8, whether carried whole or
joined from pieces, SHOULD display it anyway rather than discarding it,
replacing each part it cannot decode with a placeholder symbol such as U+FFFD
REPLACEMENT CHARACTER. While it is still reassembling a string, a receiver
SHOULD NOT place a placeholder for an incomplete sequence at the start or end
of a piece, since the neighboring piece may complete it. Once reassembly gives
up, such a sequence is replaced like any other.

## ARNCE {#arnce}

ARNCE (Amateur Radio Numeric Callsign Encoding), also called HAM-64, packs a
short alphanumeric string of up to 12 characters into 2, 4, 6, or 8 bytes. Its
encoding is defined by the
[ARNCE specification](https://github.com/arngll/arnce-spec/blob/main/n6drc-arnce.md). For example, `SJC` encodes as
`0x7853`.

## Base58 {#base58}

Keys shown to people, such as in URIs and QR codes, use base58, which avoids
visually ambiguous characters such as `0`, `O`, `I`, and `l`. UMSH uses the
alphabet:

```text
123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz
```

A 32-byte value encodes as exactly 44 digits: the value read as a big-endian
unsigned integer, written in base 58 with the most significant digit first,
and padded on the left with `1`, the zero digit. A decoder rejects input that
is not exactly 44 digits, contains a character outside the alphabet, or
encodes a value greater than 2<sup>256</sup> − 1.

## Security Considerations {#security-considerations}

Every encoding here is read from untrusted input. A parser bounds each length
by the data that remains and treats a violation as malformed, rather than
reading past the end of the data.

### Options Block {#options-vector}

Option 3 with value `01`, option 9 with value `AB CD`, and option 40 with an
empty value, followed by the data `68 69`:

```text
31 01          option 3: delta 3, length 1
62 AB CD       option 9: delta 6, length 2
D0 12          option 40: delta 13 + 0x12 = 31, length 0
FF             end marker
68 69          data
```
