This UEP defines the URIs that name UMSH things outside a packet: a node, a
group, and a CoAP resource on a node. A URI fits in a QR code, a link, or a
text message, and carries what a person needs to reach the thing it names.

## Syntax {#syntax}

A node or group is named by a `umsh` URI:

```text
umsh:<kind>:<value>[:<bundle>][?<parameters>]
```

`<kind>` is `n` for a [node](#node-uri), `gs` for a [group named by a
string](#named-group-uri), or `gk` for a [group named by its
key](#group-key-uri). A parser also accepts `cs` as `gs` and `ck` as `gk`,
which are deprecated; a sender MUST NOT write them. The scheme is matched
without regard to ASCII case, as
[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) requires. Everything after
it is case-sensitive: the kind, base58 digits, and parameter names. A parser
rejects a URI whose kind is not one of these or those aliases. A fragment is
ignored.

The URI has no authority, so everything between the scheme and the `?` is
its path, and the colons divide it into a kind, a value, and for a node, an
optional bundle.

### Percent-Encoding {#percent-encoding}

Text in a URI, a group name or a parameter value, is UTF-8 percent-encoded as
[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) defines.

- A sender encodes every byte except the unreserved characters `A`–`Z`,
  `a`–`z`, `0`–`9`, `-`, `.`, `_`, and `~`, as `%` and two uppercase
  hexadecimal digits. So a space, `:`, `?`, `;`, `&`, `=`, and `+` are all
  escaped.
- A parser decodes `%` and two hexadecimal digits of either case to the byte
  they spell. `+` is not a space. It rejects a URI that has a `%` without two
  hexadecimal digits after it, whose escapes spell bytes that are not valid
  UTF-8, or that contains a raw space, or an ASCII control character, U+0000
  to U+001F or U+007F, written raw or spelled by an escape.

A parser splits the path at its colons, and the query into items at `;` and
`&`, each at its first `=`, and only then decodes a group name or the value of
`n` or `r`. An escaped separator therefore belongs to the text it is in, and
decoding happens once. The kind, the base58 digits, the parameter names, and
the value of `mh` are matched as written, so an escaped one is not
recognized.

### Parameters {#parameters}

A group URI may end in a query of parameters, each `name=value`, written
`?` before the first and `;` between them, as in
`?n=Trail%20Crew;mh=3;r=SJC`. A parser also accepts `&` between parameters.
Only [group URIs](#group-uris) define parameters. A parameter that a URI's
kind does not define is ignored, as is a parameter whose name is not defined.
A parameter that appears more than once takes the value of its last
occurrence.

A parameter's value is a suggestion. A parameter that is malformed, as each
parameter's definition describes, is ignored, and the URI is accepted
without it.

## Node URI {#node-uri}

```text
umsh:n:<address>[:<bundle>]
```

- `<address>`: the node's [address](uep-0004.md#addresses) in
  [base58](uep-0003.md#base58): exactly 44 digits. The base16 form is not
  accepted in a URI. The digits are case-sensitive, so a parser MUST NOT
  change their case.
- `<bundle>`: an optional [identity bundle](#identity-bundle).

A URI without a bundle names the node and says nothing more about it. A
node URI defines no parameters.

### Identity Bundle {#identity-bundle}

The bundle carries the node's identity so that a person who scans the URI
holds a name, a role, and any location the node chose to share, not only a
key. It is the node's [identity payload](uep-0011.md#payload) without its
payload type: `ROLE`, `CAPS`, `OPTIONS`, and when signed, the `0xFF` end
marker and the signature. It is written in [variable-length
base58](#variable-base58).

A reader treats the bundle as [UEP-0011](uep-0011.md#signatures) treats an
identity heard outside any frame. The bundle has no frame to authenticate it,
so a receiver believes it only when its embedded signature verifies against
the address in the same URI. A bundle without a signature is not believed. A
receiver MAY show it, marked as unauthenticated, but SHOULD NOT let it
replace details held about the node. A bundle whose signature does not verify
is not believed at all.

A bundle that is not valid base58 or is not a valid identity payload is
ignored, and the URI still names the node.

A sender MUST NOT write a bundle that is not a valid identity payload. An
identity payload fits in a packet, so a bundle is a few hundred digits. A
receiver MAY ignore a bundle of more than 2048 digits, because decoding
base58 takes time quadratic in its length and the URI arrives from outside.

### Variable-Length Base58 {#variable-base58}

[UEP-0003](uep-0003.md#base58) defines the encoding of a 32-byte value. A
bundle has no fixed length and uses the same digits and the same
big-endian reading, without padding to a width:

- Each leading `0x00` byte is written as one `1` digit.
- The remaining bytes, read as a big-endian unsigned integer, are written in
  base 58 with the most significant digit first and no leading `1` digits.
- An empty input is written as no digits.

A decoder reverses this: each leading `1` is a `0x00` byte, and the rest is
the integer's big-endian bytes without leading zeros. It rejects a character
outside the alphabet.

## Group URIs {#group-uris}

Two URI kinds name a group. They differ in how they carry the group's key.

### Named Group {#named-group-uri}

```text
umsh:gs:<name>[?<parameters>]
```

`<name>` is a [named group](uep-0008.md#named-groups)'s name,
[percent-decoded](#percent-encoding), so the URI `umsh:gs:Public` names the
group `Public`. A node then derives the group's key from the decoded name as
[UEP-0008](uep-0008.md#named-groups) defines, which folds ASCII case: `umsh:gs:Public`,
`umsh:gs:public`, `umsh:gs:PUBLIC`, and `umsh:gs:%50ublic` all name one group.

A node rejects the URI when the name is empty, or when [UEP-0008](uep-0008.md#named-groups) rejects the
decoded name: it is not ASCII, or it is too long. Percent-encoding offers no
way around the ASCII rule, because the name is checked after it is decoded.

A name that contains `:` is written `%3A`. A URI that has a third segment, as
in `umsh:gs:a:b`, is rejected, so that a name cut short at a colon is never
joined in place of the name its sender meant.

A named group offers no secrecy, as [UEP-0008](uep-0008.md#security-considerations)
says, and neither does the URI that names it.

### Group Key {#group-key-uri}

```text
umsh:gk:<key>[?<parameters>]
```

`<key>` is the 32-byte [group key](uep-0008.md#groups) in
[base58](uep-0003.md#base58): exactly 44 digits. A node that receives the URI
holds the key and can derive the rest of the group's keys from it. This is how
a [simple private group](uep-0008.md#simple-private-groups) is shared. A URI
with a third segment is rejected.

### Group Parameters {#group-parameters}

A group URI suggests settings for the node that joins it. All three are
optional.

| Name | Value | Suggests |
|---|---|---|
| `n` | Text | A name for the group, such as one a person gave it. Empty text is ignored |
| `mh` | 0 to 15 | The most [flood hops](uep-0014.md#flood-radius) a sender allows its traffic in this group. Written as one or two decimal digits. A value that is anything else, or above 15, is ignored |
| `r` | A [region](uep-0014.md#region-encoding) string form | The region that senders in this group confine their floods to, as the [Region Code option](uep-0014.md#region-code) names it. A string that [parsing](uep-0014.md#region-parsing) rejects is ignored |

A sender MUST NOT write an `mh` above 15 or an empty `n`.

A node that joins a group by URI MAY use the parameters as the starting point
of its own settings for the group, and a person may change them. A receiver of
the group's traffic never applies them to it: a packet is accepted or
dropped by the rules of the packet's own UEPs, whatever its group's URI said.

## CoAP URI {#coap-uri}

```text
coap-umsh://<address>[/<path>][?<query>]
```

A `coap-umsh` URI names a [CoAP](https://www.rfc-editor.org/rfc/rfc7252)
resource on a node. The authority is the node's address, as for a node URI:
44 base58 digits, without a user, port, or hint. The path and query are those
of a `coap` URI, and compose into the request's Uri-Path and Uri-Query as
[RFC 7252 §6](https://www.rfc-editor.org/rfc/rfc7252#section-6) describes.

The authority is case-sensitive. Lowercasing it, as
[RFC 3986 §6.2.2.1](https://www.rfc-editor.org/rfc/rfc3986#section-6.2.2.1)
allows for a registered name, names a different key.

This UEP defines how a resource is named. How a CoAP message is carried to
the node is outside it.

## Registry Considerations {#registry-considerations}

This UEP creates no registry and allocates no value. The `umsh` and
`coap-umsh` URI schemes are not registered with IANA.

## Security Considerations {#security-considerations}

**A URI is input from outside.** A QR code, a link, or a message supplies it,
and whoever made it chose every byte. A parser bounds the length it will
decode and applies the rules above to each piece. It ignores an optional
parameter or bundle it cannot use, and rejects a URI whose escapes are
damaged, so that what it names is never guessed from damaged text. It never
saves a contact, joins a group, or sends a request merely because it read a
URI; a person decides.

**A group-key URI is a key.** Anyone who reads the URI can read the group's
encrypted traffic, send to it, and write to it as any member
([UEP-0008](uep-0008.md#security-considerations)). A URI is as secret as the
place it was put: a QR code shown on a screen, a message sent in the clear, a
clipboard history, or a log. A node does not write one into a log, and
sends one only where its recipient alone can read it.

**Parameters are claims by whoever wrote the URI.** A name can be
misleading, such as one that imitates another group's, and can contain
control or bidirectional characters. A node shows it as plain text, bounded
in length, beside the group's other identifying details, and does not take it
as the group's identity. `mh` and `r` change how much the joining node
floods, so they are suggestions a person can see and refuse: a large `mh`
widens a flood, and an `r` where no repeater serves the group can keep its
traffic from getting out. A parameter is never applied to the group's
received traffic.

**A bundle shows that its signer holds the key, and nothing more.** Anyone
can make a consistent URI for a key they hold. The signature binds the
details to the address in the URI, so a person must still check the address
against what they expect, as the display of a [44-digit
address](uep-0004.md#presentation) allows. An unsigned bundle is a
claim by whoever wrote the URI. A signed bundle carries no freshness, so a
captured one verifies wherever it is put back, as
[UEP-0011](uep-0011.md#claims) explains; its Timestamp option lets a
node prefer later details but does not prove that these are the node's
current ones.

**Case.** Base58 is case-sensitive. A system that changes the case of a URI
changes the key it names into a different or invalid one, and a message to it
is lost. A named group's name folds case, so two URIs that differ only in
ASCII case name one group.

**Dereferencing a `coap-umsh` URI is a request.** Reading one is not
authorization to send it, since a request can change what a node does. The
address in the authority authenticates the node that answers, not the
person who wrote the URI.

### Node URIs {#node-vectors}

```text
umsh:n:GySVDr1omr3GTodgWFH7qD1ZKav9C5NMPFjdpwb33LvU
```

```text
umsh:n:GySVDr1omr3GTodgWFH7qD1ZKav9C5NMPFjdpwb33LvU:9NPVXctGv5bNRLpyNDMXGYvne4bHwV8WxQ1xQoEiA3gemRET41UnDHRfTmWvYSu4TMKK441imEcJSVx3LCwyqj4kY4HZPAJSTrgeazDPGM1nBn59zF
```

`02 06 05 41 6C 69 63 65 13 B2 59 15 11 F4 14 6B 36 EC 80`. It is not
believed, and is shown as unauthenticated at most:

```text
umsh:n:GySVDr1omr3GTodgWFH7qD1ZKav9C5NMPFjdpwb33LvU:NVBjSY2wfbwPypTziMyej18fh
```

### Group URIs {#group-vectors}

Each of these names the group whose key is `FB 9B 7A DD … 1B 51`, as
[UEP-0008 Appendix A](uep-0008.md#test-vectors) lists:

```text
umsh:gs:Public
umsh:gs:public
umsh:gs:PUBLIC
umsh:gs:%50ublic
```

A parser also reads each of these through the deprecated kinds, as the first
group above and as the group key `5A` × 32 that the next vector writes with
`gk`:

```text
umsh:cs:Public
umsh:ck:75hbt6uvDqjPZ9WgFtMhBnTeyHw7cinoHiz4FD2vEz2d
```

The group key `5A` × 32 with parameters, whose name is `Trail Crew`, whose
flood limit is 3, and whose region code is `0x7853`:

```text
umsh:gk:75hbt6uvDqjPZ9WgFtMhBnTeyHw7cinoHiz4FD2vEz2d?n=Trail%20Crew;mh=3;r=SJC
```

A name that contains the separators of a URI, `a?b;c=d&e/f`, as a parameter
value:

```text
?n=a%3Fb%3Bc%3Dd%26e%2Ff
```

### Rejected and Ignored {#rejected-vectors}

A node rejects each of these URIs:

| URI | Reason |
|---|---|
| `umsh:gs:` | Empty name |
| `umsh:gs:caf%C3%A9` | The decoded name is not ASCII |
| `umsh:gs:a:b` | A third segment |
| `umsh:gs:100%` | A `%` without two hexadecimal digits |
| `umsh:gs:public%00x` | A control character |
| `umsh:gk:75hbt6uvDqjPZ9WgFtMhBnTeyHw7cinoHiz4FD2vEz2d:x` | A third segment |
| `umsh:gk:75hbt6uvDqjPZ9WgFtMhBnTeyHw7cinoHiz4FD2vEz2d?n=%FF` | An escape that is not UTF-8 |
| `umsh:gk:GySVDr1omr3GTodgWFH7qD1ZKav9C5NMPFjdpwb33Lv` | A key of 43 digits |
| `umsh:x:GySVDr1omr3GTodgWFH7qD1ZKav9C5NMPFjdpwb33LvU` | An undefined kind |

A parser accepts each of these group URIs and ignores the parameter shown:

| URI ends | Ignored |
|---|---|
| `?mh=16` | `mh`, above 15 |
| `?mh=x` | `mh`, not a number |
| `?n=` | `n`, empty |
| `?r=` | `r`, not a region |
| `?q=1` | `q`, not defined |
| `?mh=%33` | `mh`, not decimal digits as written |
| `?%6E=Evil` | `%6E`, not a defined name as written |
