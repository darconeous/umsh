This UEP defines flood hops: how a repeater accounts for them in the flood
hop count, the flood radius, the contention window a flood hop waits out
before it is transmitted, the Region Code option that confines a flood, the
encoding of region codes, and the Supported Regions identity option.
Its forwarding rules apply to flood hops only
([UEP-0012](uep-0012.md#hop-kinds)).

## Flood Hops {#flood-hops}

A **flood hop** is a forward that spends one from `FHOPS_REM`
([UEP-0005](uep-0005.md#fhops)). The originator's own transmission is not a
flood hop, and neither is a [routed hop](uep-0014.md#routed-hop).

A path's [hop count](uep-0012.md#terminology) equals `FHOPS_ACC + 1` exactly
when no source route carried the packet.

## Flood Hop Accounting {#fhops-accounting}

Flood hop accounting is a [flood-only check](uep-0012.md#flood-checks) and an
[edit](uep-0012.md#edits):

- **Check.** A repeater does not flood-forward a packet that carries no
  `FHOPS`, whose `FHOPS_REM` is zero, or whose `FHOPS_ACC` is 15, which no
  further flood hop can count.
- **Edit.** A repeater that flood-forwards a packet decrements `FHOPS_REM`
  and increments `FHOPS_ACC`. This is the first edit
  [UEP-0012](uep-0012.md#edits) makes.

A repeater MUST NOT change `FHOPS` on a routed hop, including the routed hop
that removes the last hint of a source route. The next repeater pays the first flood hop
([UEP-0014](uep-0014.md#route-end)).

A UEP that defines a link may permit a forwarder on that link to lower
`FHOPS_REM`, and says how. `FHOPS_REM + FHOPS_ACC` is otherwise the
same in every copy of a packet, and normally equals the limit its sender set.

## Flood Radius {#flood-radius}

A flood reaches at most **15 flood hops**: a path of 16 hops when no source
route is involved. The limit bounds the flood, not the path. A longer path
combines a source route with a flood
([UEP-0014](uep-0014.md#flood-budget)).

A sender sets `FHOPS_ACC` to zero ([UEP-0005](uep-0005.md#fhops)), so
`FHOPS_REM + FHOPS_ACC` from a conforming sender never exceeds 15. A sender
whose flood budget is zero SHOULD omit `FHOPS` rather than send a
`FHOPS_REM` of zero.

`FHOPS_ACC` tells a receiver how many flood hops a packet traversed: one less
than its hop count, unless a source route carried it part of the way.
[UEP-0015](uep-0015.md) uses it to route acknowledgments.

## Flood Contention Window {#contention-window}

A repeater eligible to flood-forward a copy that arrived
[measured](uep-0012.md#measured) or on a
[shared medium](uep-0012.md#shared-medium) SHOULD NOT transmit it at once.
It waits a **contention delay** that grows with the power of the signal it
received, shrinks with the signal's quality, and is longest for a reception
near the [demodulation floor](uep-0011.md#snr-floor). A repeater that heard
the packet cleanly but faintly, and so is likely farther from its sender,
goes first. One that heard it strongly waits longer, and one that barely
heard it goes last. The others overhear the first forward and
[give way](uep-0012.md#give-way).

The contention delay is part of [scheduling](uep-0012.md#scheduling), which
adds [`D_ack`](uep-0012.md#ack-hold-back) and any delay later UEPs define. A
copy that makes a pending forward give way sets a new delay by the same
rules, measured on that copy.

### Parameters {#contention-parameters}

The nodes of one mesh SHOULD use the same values, and an implementation
SHOULD use these defaults unless a deployment sets others:

| Parameter | Default |
|---|---|
| `SNR_low` | `SNR_floor + 6 dB`, unless [raised](#snr-low) |
| `SNR_high` | `max(SNR_floor + 18 dB, SNR_low + 1 dB)` |
| `RSSI_low` | −100 dBm |
| `RSSI_high` | −70 dBm |
| `W_min` | 0 |
| `W_max` | `T_frame / 2` |
| `W_jitter` | `T_frame / 10` |

`SNR_floor` is the [demodulation floor](uep-0011.md#snr-floor) at the
spreading factor in use, and [`T_frame`](uep-0011.md#t-frame) is the frame
duration. A deployment that sets its own values keeps `RSSI_high` above
`RSSI_low` and `W_max` at or above `W_min`.

### Measured Arrivals {#contention-formula}

For a copy that arrived [measured](uep-0012.md#measured), with the SNR and
RSSI of that reception:

```text
quality = clamp((SNR − SNR_low) / (SNR_high − SNR_low), 0, 1)
signal  = clamp((RSSI − RSSI_low) / (RSSI_high − RSSI_low), 0, 1)

if SNR < SNR_low:
    W = W_max + W_jitter
else:
    W = W_min + (W_max − W_min) × max(1 − quality, signal)

delay = W + uniform(0, W_jitter)
```

A reception below `SNR_low` waits out the whole window and one jitter range
before drawing its own jitter, so it is forwarded only if no repeater that
heard the packet within the band forwarded it first.

### Unmeasured Arrivals {#contention-unmeasured}

- **[Shared medium](uep-0012.md#shared-medium).** Every node on the medium
  heard the copy equally, and nothing ranks them. The delay is drawn over the
  whole extent of the measured window:

  ```text
  delay = W_min + uniform(0, (W_max − W_min) + W_jitter)
  ```

- **[Point-to-point](uep-0012.md#point-to-point).** Only this repeater heard
  the copy, so there is no contention to resolve, and the contention delay is
  zero.

### Raising SNR_low {#snr-low}

`SNR_low` is `SNR_floor + 6 dB` unless a UEP raises it. A UEP that sets a
minimum SNR for forwarding may raise `SNR_low` to that minimum, so that the
quality scale starts where forwarding does. `SNR_high` then follows its
definition, and the scale keeps a positive span. The proposed
[Signal-Quality Filtering](index.md#proposals) UEP does so.

## Region Code Option (11) {#region-code}

The **Region Code** option confines a flood to repeaters that serve one of
the regions it names.

- **Attributes:** forwarding-critical, dynamic
  ([UEP-0005](uep-0005.md#option-attributes)).
- **Value:** a 2-byte [region code](#region-encoding), big-endian. A value of
  any other length cannot be interpreted
  ([UEP-0005](uep-0005.md#criticality)): a repeater does not forward the
  packet, and its delivery is unaffected.
- **Repeats:** a packet may carry several Region Code options, and names
  every region they list.

Only the sender, or the first repeater to flood-forward a packet that carries
none, sets a packet's regions ([Region Insertion](#region-insertion)). A
sender that needs its packet confined to a region includes the option
itself.

### Region Policy {#region-policy}

Region policy is a [flood-only check](uep-0012.md#flood-checks).

A repeater may be configured with a set of **regions** it forwards for. It
compares region codes, so a region configured by its
[string form](#region-encoding) is compared by the code it derives.

- A repeater configured with one or more regions MUST NOT flood-forward a
  packet that carries Region Code options none of which names one of them. It
  forwards a packet any one of whose codes names one of them.
- A packet that carries no Region Code option is forwarded whatever the
  repeater's regions.
- A repeater configured with no regions makes no regional claim and applies
  no restriction.

Region policy applies on every [arrival class](uep-0012.md#arrival-classes).
A repeater MUST NOT apply it on a routed hop, including the hop that removes
the last hint of a source route ([UEP-0014](uep-0014.md#routed-hop)).

### Region Insertion {#region-insertion}

Region insertion is the third [edit](uep-0012.md#edits), made on flood hops
only.

A repeater may be configured with a **default region**, independently of its
regions: a region code asserts where a packet is, not which regions the
repeater carries.

- When flood-forwarding a packet that carries no Region Code option, a
  repeater with a default region SHOULD insert it. A repeater without one
  forwards the packet untagged.
- A repeater MUST NOT change or remove a Region Code option, and MUST NOT add
  one to a packet that already carries one or more.

An untagged source-routed packet is first tagged by the repeater that
receives it with an empty route, which is the first to flood it
([UEP-0014](uep-0014.md#route-end)), not by the repeater that emptied the
route.

Copies that differ only in their Region Code options share a
[forwarding identity](uep-0012.md#forwarding-identity). When repeaters with
different default regions hear one untagged packet, its region is the one
inserted by whichever forwards it first, and the others suppress their
copies as duplicates.

An inserted option counts toward the size of the forwarded packet, which
must still [fit the outgoing link](uep-0012.md#link-fit). A repeater does not
omit the insertion to make room.

A default region is conventionally the three-letter short code of the
nearest commercial airport, or of a metro area that has one. A country or a
subdivision is usually too broad to confine a flood.

## Region Code Encoding {#region-encoding}

A **region code** is a 2-byte value derived from a region's **string form**:
a [short code](#short-codes), a [region name](#named-regions), or a
[literal code](#literal-codes).

### Case Folding {#region-folding}

Derivation ignores ASCII case, so strings that differ only in ASCII case name
the same region. [ARNCE](uep-0003.md#arnce) encodes `A`–`Z` and `a`–`z`
alike, and the hash folds `A`–`Z` to `a`–`z` before hashing, altering no other
byte.

Folding is ASCII only. Folding the rest of Unicode depends on locale, and two
nodes that folded one name differently would make it two regions.

### ARNCE Chunks {#region-chunk}

A region code is read as one 16-bit ARNCE chunk, which holds three
characters `c0`, `c1`, and `c2`:

```text
value = c0 × 1600 + c1 × 40 + c2
```

| Index | Character |
|---:|---|
| 0 | Absent |
| 1–26 | `A`–`Z` |
| 27–36 | `0`–`9` |
| 37 | `/` |
| 38 | `-` |
| 39 | `^` |

Values from 64000 (`0xFA00`) up are not chunks. A code **reads as letters**
when it decodes to one to three letters followed only by absent characters:
`c0` is a letter, and either `c1` and `c2` are both letters, `c1` is a letter
and `c2` absent, or both are absent.

### Short Codes {#short-codes}

A **short code** is one to three ASCII letters or digits, encoded as one
ARNCE chunk with any unused trailing positions absent. By convention, three
letters are an IATA airport or metro code, and two letters are an
[ISO 3166-1](https://www.iso.org/iso-3166-country-codes.html) alpha-2
country code or a bare subdivision code.

| Short code | Region code |
|---|---|
| `SJC` | `0x7853` |
| `MFR` | `0x5242` |
| `US` | `0x8638` |
| `WA` | `0x8FE8` |

`/`, `-`, and `^` MUST NOT appear in a short code, though ARNCE spells them,
so that a short code is written in letters and digits alone.

No two short codes share a code. An all-letter short code is also exclusive:
no named region derives one ([Letter Transform](#letter-transform)). A short
code that contains a digit, such as `W7` or `5X2`, may equal a code derived
from a name: Rogue Valley's code, `0xC0F9`, is also the short code `38A`.
An implementation MUST NOT display a region code as a digit-bearing short
code.

### Named Regions {#named-regions}

The code of a **named region** is the first two bytes, big-endian, of the
SHA-256 hash ([FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final))
of its [prepared](#region-parsing) and [folded](#region-folding) name,
encoded as UTF-8. If that value reads
as letters, the [letter transform](#letter-transform) is applied to it.

#### Letter Transform {#letter-transform}

```text
TRANSFORM_BASE  = 27 × 1600              = 0xA8C0
TWO_LETTER_BASE = TRANSFORM_BASE + 26³   = 0xED68
ONE_LETTER_BASE = TWO_LETTER_BASE + 26²  = 0xF00C

a = v div 1600
b = (v div 40) mod 40
c = v mod 40
letter(x) = 1 ≤ x ≤ 26

if not letter(a):                 result = v
else if letter(b) and letter(c):  result = TRANSFORM_BASE + (a − 1) × 676 + (b − 1) × 26 + (c − 1)
else if letter(b) and c = 0:      result = TWO_LETTER_BASE + (a − 1) × 26 + (b − 1)
else if b = 0 and c = 0:          result = ONE_LETTER_BASE + (a − 1)
else:                             result = v
```

The three cases fill consecutive blocks, longest first, from `0xA8C0` to
`0xF025`, and vacate the 18,278 codes that read as letters. No transformed
value reads as letters, so a named region never derives the code of an
all-letter short code, and every code that reads as letters is that short
code.

Two names may still derive one code, as may a name and a digit-bearing short
code. A flood is local, so such a collision matters only within one area,
where it is resolved by making a name more specific.

### Literal Codes {#literal-codes}

A string of `0x` followed by exactly four hexadecimal digits names the code
those digits spell. The prefix and the digits may be written in either case.
Such a string is never a region name.

A literal is also how a code is [displayed](#region-display) when it does not
read as letters and its name is unknown, so a region list read off the air can be fed back in. A
string of one to three characters is a short code first: `0x1` is the short
code of the characters `0`, `x`, and `1`.

### Parsing a String Form {#region-parsing}

A node derives the code of a string form in this order:

1. Remove leading and trailing ASCII white space: space, tab, line feed, form
   feed, and carriage return. Other white space is part of the string.
2. Reject an empty string.
3. Reject a string that contains any other control character: U+0000 to
   U+001F, U+007F, or U+0080 to U+009F.
4. Replace each remaining run of ASCII white space with one space.
5. Reject a string longer than 24 bytes of UTF-8.
6. If the string is a [literal code](#literal-codes), use it.
7. If the string is a [short code](#short-codes), encode it.
8. Otherwise, hash it as a [region name](#named-regions).

A region name MUST NOT exceed **24 bytes** of UTF-8 once prepared this way.
The bound lets a list of names fit in an
[identity payload](#supported-regions).

A name that contains non-ASCII characters hashes its UTF-8 bytes as they
are, so one name written in two Unicode normalization forms derives two
codes. A node that takes a region name from a person SHOULD convert it to
Normalization Form C ([UAX #15](https://www.unicode.org/reports/tr15/))
before it stores or sends it.

### Display {#region-display}

A code that reads as letters is displayed as those letters, in uppercase. Any
other code whose name is not known is displayed as a literal: `0x` and four hexadecimal digits, which
SHOULD be uppercase, as in `0xC0F9`.

### Capitalization {#region-capitalization}

Folding applies to derivation and comparison, not to storage. A region held or
carried as a string, such as a repeater's configured regions or a
[Supported Regions](#supported-regions) entry, keeps the capitalization it was
written with. A short code is displayed in uppercase whatever case it was
written in.

## Supported Regions (Identity Option 4) {#supported-regions}

A repeater lists the regions it flood-forwards for in the **Supported
Regions** [identity option](uep-0010.md#identity-options), one option per
region. The option repeats, as UEP-0010 permits an option's definition to
say.

- Each value is a region's string form: its short code if it has one,
  otherwise its name or a literal code. It is 1 to 24 bytes, in the
  capitalization the region was written with. A region's code can always be
  derived from its string form, while a name cannot be recovered from a code.
- A sender MUST NOT list more than 10 regions. The identity payload must still fit its
  packet, so a node whose list does not fit omits regions. The option names
  regions the node forwards for without promising to name all of them.
- A node that omits the option makes no claim about its region policy.

A receiver compares entries by the codes they derive. It ignores an entry
that is empty, longer than 24 bytes, not valid UTF-8, or rejected by
[parsing](#region-parsing), and keeps at most the first ten entries it does
not ignore, without discarding the identity. An option whose every entry is ignored makes no
claim.

## Security Considerations {#security-considerations}

**Dynamic fields.** `FHOPS` and Region Code options are not covered by the
MIC. A malicious forwarder can rewrite `FHOPS`, resetting `FHOPS_ACC` and raising
`FHOPS_REM` to widen a flood to as many as 15 flood hops beyond itself within
the bounds of [duplicate suppression](uep-0012.md#duplicate-suppression), or
narrow it, and
can strip, rewrite, or add region codes. The rules here bind conforming
repeaters only.

**First insertion wins.** A repeater that tags an untagged packet with a
region no one serves confines its flood to repeaters configured with no
regions. A sender that cares where its packet floods tags it itself.

**Contention.** The contention window is cooperative. A repeater that ignores
it costs the mesh efficiency, not correctness.

**Location.** A region code discloses coarse location: the sender's, or that
of the repeater that tagged the packet. Supported Regions discloses where a
repeater operates, and is a [claim](uep-0010.md#claims), not a proof.

**Collisions.** A region code is 16 bits, and anyone can derive the code of
any name. Two regions that share a code carry each other's floods where both
are served, a local nuisance with a local fix.

## Appendix B: Flood Forwarding Examples {#flood-vectors}

These frames are built from the unicast in
[UEP-0005](uep-0005.md#unicast-vector), with the same payload and MIC and no
options. The MIC is unchanged throughout, because `FHOPS`, the `H` bit, and
dynamic options are outside the [associated data](uep-0007.md#associated-data).

The packet as sent, `FHOPS_REM` 4 and `FHOPS_ACC` 0, untagged:

```text
D1 40 6C 28 FD ED 54 A5 E0 00 00 00 0A FF B7 C4
59 EC 72 BD EA E9 59 DB 86 BA AD 14 9C 92 5F B4
0B
```

Flood-forwarded by a repeater whose default region is `SJC`. `FHOPS` becomes
3/1, and the repeater inserts option 11 with the value `78 53`:

```text
D1 31 6C 28 FD ED 54 A5 E0 00 00 00 0A B2 78 53
FF B7 C4 59 EC 72 BD EA E9 59 DB 86 BA AD 14 9C
92 5F B4 0B
```

Flood-forwarded instead by a repeater with no default region, untagged. A
repeater whose regions are `MFR` alone and that has no default region forwards
the same:

```text
D1 31 6C 28 FD ED 54 A5 E0 00 00 00 0A FF B7 C4
59 EC 72 BD EA E9 59 DB 86 BA AD 14 9C 92 5F B4
0B
```

The tagged copy, flood-forwarded again by a repeater whose regions include
`SJC`, or by one configured with no regions whose default region is `MFR`. `FHOPS` becomes 2/2, and the
region code is carried unchanged:

```text
D1 22 6C 28 FD ED 54 A5 E0 00 00 00 0A B2 78 53
FF B7 C4 59 EC 72 BD EA E9 59 DB 86 BA AD 14 9C
92 5F B4 0B
```

A repeater whose regions are `MFR` alone does not forward the tagged copy.
