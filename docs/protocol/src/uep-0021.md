This UEP defines the two default groups, `public` and `EMERGENCY`: how a node
recognizes them, and the rules their traffic follows.

## The Default Groups {#default-groups}

Both default groups are [named groups](uep-0008.md#named-groups):

| Group | Canonical name | Purpose |
|---|---|---|
| [`public`](#public) | `public` | Open group conversation |
| [`EMERGENCY`](#emergency) | `emergency` | Emergency communication |

`EMERGENCY` is written in capitals for emphasis, and its key is derived from
the canonical name. The keys, group IDs, and group hints of both are given in
[UEP-0008 Appendix A](uep-0008.md#test-vectors).

A group is a default group when its group key is that group's key, however the
node obtained the key. A group whose [group hint](uep-0007.md#group-hint)
matches a default group's, but whose key differs, is not that group, and the
rules of this UEP do not apply to it. Either group is shared as a
[named-group URI](uep-0019.md#named-group-uri), like any named group.

A text message by group unicast on a default group is a repair request. A
sender MUST NOT send a text message by group unicast on either default group
other than a [Message Resend Request](uep-0020.md#resend-request) that carries
the [Group Resend](uep-0020.md#group-resend) option, and a receiver does not
accept or display any other. A one-to-one conversation uses unicast instead.

A node that presents group conversations to a person SHOULD hold both groups
from its first start. Such a node lets the person leave either, like any other
group.

## Flood Hops {#flood-hops}

A sender MUST NOT set `FHOPS_REM` ([UEP-0005](uep-0005.md#fhops)) above 10 on
any packet it sends in either default group, by multicast or by group unicast.
It MAY set less. Other groups may use the full
[flood radius](uep-0014.md#flood-radius).

## `public` {#public}

`public` is the default group conversation, open to any node that knows its
name.

A sender MUST set the FCF's `S` bit, carrying its full
[source address](uep-0005.md#source-address), on every
[text message](uep-0020.md#payload) it sends by multicast on `public`. A
receiver does not accept or display a text message by multicast on `public`
whose source is a node hint. Such a message holds no position in its sender's
stream, and does not fill a gap.

## `EMERGENCY` {#emergency}

`EMERGENCY` carries emergency communication. Its text messages are readable by
any node in range and attributable to their sender.

A sender follows these rules for every
[text message](uep-0020.md#payload) on `EMERGENCY`, whether by multicast or by
group unicast:

- It MUST NOT encrypt it: the SCF's [`E` bit](uep-0005.md#scf) is clear. A
  sender SHOULD NOT encrypt any other packet on `EMERGENCY` either.
- It MUST set the FCF's `S` bit, carrying its full
  [source address](uep-0005.md#source-address).
- When it sends the text message by multicast, it MUST sign it with a
  [frame signature](uep-0007.md#frame-signatures). This includes a
  [response](uep-0020.md#responding) to a resend request, which is sent by
  multicast to the group, whether it is the message or
  [Message Unavailable](uep-0020.md#unavailable). A resend request, which
  arrives by group unicast, is attributed to its source by its keys
  ([UEP-0008](uep-0008.md#sender-attribution)) and need not be signed.

A receiver does not accept or display a text message on `EMERGENCY` that is
encrypted, whose source is a node hint, or that arrives by multicast without
a signature that [verifies](uep-0007.md#signature-verification). Such a
message holds no position in its sender's stream, and does not fill a gap.

A repeater SHOULD forward a packet in `EMERGENCY` ahead of the other packets it
has waiting to forward.

### Emergency Use {#emergency-use}

A node MUST NOT originate a packet on `EMERGENCY` at a person's request until
that person has confirmed, in answer to an explicit prompt, that the traffic
concerns an emergency. This covers every transmission a person starts:
messages, reactions, edits, deletions, resends, and requests for missing
messages.

A node MUST NOT originate a text message on `EMERGENCY` without a person's
request, except to repair a conversation as
[Message Repair](uep-0020.md#repair) allows.

### Test Messages {#emergency-test-messages}

[UEP-0020](uep-0020.md#test-messages) defines test messages on `EMERGENCY`,
for which a receiver raises no alert unless a person has opted in.

## Security Considerations {#security-considerations}

**Default groups are public.** Anyone can derive either key, read any packet
in either group, and send to it, as for any
[named group](uep-0008.md#security-considerations). Encrypting traffic on
`public` hides it only from a node that does not try to read it. A group
unicast on a default group reveals its source and destination to anyone who
knows the name, which is why one-to-one conversations do not use it. A group
that only shares a default group's hint is not that group.

**A full address is not attribution.** Carrying the full source address on
`public` lets a receiver name the claimed sender and reach it, but an
unsigned multicast's source is still a claim that any member can forge
([UEP-0008](uep-0008.md#sender-attribution)). Only a frame signature
attributes a multicast. On `EMERGENCY`, every accepted text message by
multicast is signed, so a member cannot impersonate another there.

**Emergency traffic exposes its sender.** A text message on `EMERGENCY` is
unencrypted and carries its sender's full address and signature, so anyone in
range learns which address sent it and what it says, and can show that the
address's key signed it. The emergency-use prompt makes a person confirm this
before a node sends on their behalf. It guards against accidental use, not
against a sender determined to misuse the group, who can sign with a new
address. A signature names a person only as far as a receiver has bound that
address to one, and a handle can imitate another's.

**Flood hops are a sender's limit.** Nearly every node holds the default
groups, so the 10-hop limit bounds the load their traffic places on the mesh.
Only senders apply it. A repeater forwards without verifying a packet's MIC
([UEP-0013](uep-0013.md#cache-lifetime)), and `FHOPS` is not covered by the
MIC ([UEP-0005](uep-0005.md#fhops)), so a packet that exceeds the limit is
forwarded as any other.

**Priority can be claimed.** Anyone can send on `EMERGENCY`, so the priority
repeaters give it is open to any sender willing to send there unencrypted and
signed. A repeater that recognizes the group by its group hint alone, without
checking the MIC, also gives priority to the groups that share the hint.
