This UEP defines the layout of a UMSH packet: the frame control field, the
fields each packet type carries, the packet options framework, and the payload
type that begins a payload. It defines what a receiver needs to take a packet
apart. What the security fields mean, and how a node checks them, is defined
in [UEP-0007](uep-0007.md); how a repeater forwards a packet, in
[UEP-0013](uep-0013.md).

## Packet Layout {#layout}

A packet begins with a one-byte [frame control field](#fcf). The fields after
it depend on the packet type, in this order:

```text
+-----+-------+-----------+--------+---------+---------+---------+-------+-----+
| FCF | FHOPS | DST/GROUP |  SRC   | SECINFO | OPTIONS | PAYLOAD | [SIG] | MIC |
+-----+-------+-----------+--------+---------+---------+---------+-------+-----+
  1 B   0/1 B    0/2/3 B   0/3/32 B  0/5/7 B  variable  variable  0/64 B 0–16 B
```

- `FHOPS`: the [flood hop count](#fhops), present when the FCF's `H` bit is
  set.
- `DST`: the destination's [node hint](uep-0004.md#node-hint), on unicast.
- `GROUP`: a 2-byte [group hint](uep-0007.md#group-hint), on
  multicast and group unicast. It names the group whose key secures the
  packet.
- `SRC`: the [source address](#source-address). On multicast and group
  unicast it follows the options instead, and is encrypted when the packet
  is.
- `SECINFO`: the [security information](#secinfo), on every packet type but
  broadcast and MAC ack.
- `OPTIONS`: the packet's [options](#options).
- `PAYLOAD`: the [payload](#payload).
- `SIG`: a 64-byte Ed25519 signature
  ([RFC 8032](https://www.rfc-editor.org/rfc/rfc8032)) by the source, present
  when the SCF's `D` bit is set. It is encrypted with the payload when the
  packet is encrypted.
- `MIC`: the packet's message integrity code, 4 to 16 bytes as SECINFO
  states. A MAC ack carries a fixed 8-byte [ack trailer](#mac-ack) instead.

The [layout of each packet type](#layouts) shows which fields it carries.

## Frame Control Field {#fcf}

```text
  7   6   5   4   3   2   1   0
+-------+-----------+---+---+---+
|  VER  | PKT TYPE  | S | R | H |
+-------+-----------+---+---+---+
 2 bits    3 bits     1   1   1
```

- `VER`: the protocol version. This UEP defines version 3, with both bits
  set. Everything after the FCF depends on the version, so a receiver
  discards a packet of any other version, and a repeater does not forward it.
- `PKT TYPE`: the [packet type](#packet-types).
- `S`: set when `SRC` is a full address, and clear when it is a node hint.
  See [Source Address](#source-address).
- `R`: reserved. A sender sets it to 0, and a receiver discards a packet that
  has it set.
- `H`: set when `FHOPS` is present.

### Packet Types {#packet-types}

| Value | Name | Packet type |
|---:|---|---|
| 0 | `BCST` | [Broadcast](#broadcast) |
| 1 | `UACK` | [MAC ack](#mac-ack) |
| 2 | `UNIC` | [Unicast](#unicast) |
| 3 | `UNAR` | [Unicast, ack requested](#unicast) |
| 4 | `MCST` | [Multicast](#multicast) |
| 5 | | *Reserved* |
| 6 | `GUNI` | [Group unicast](#group-unicast) |
| 7 | `GUAR` | [Group unicast, ack requested](#group-unicast) |

A receiver discards a packet of a reserved type.

## Source Address {#source-address}

`SRC` is the packet's source, in one of two sizes:

- When `S` is clear, the source's 3-byte [node hint](uep-0004.md#node-hint).
  A receiver can process the packet only if it already holds the address the
  hint stands for.
- When `S` is set, the source's 32-byte [address](uep-0004.md#addresses). A
  receiver can process the packet with no prior state.

A MAC ack carries no `SRC`. A sender clears `S` on a MAC ack, and a receiver
ignores it there.

## Flood Hop Count {#fhops}

`FHOPS` is one byte holding two 4-bit counts:

```text
  7   6   5   4   3   2   1   0
+---------------+---------------+
|   FHOPS_REM   |   FHOPS_ACC   |
+---------------+---------------+
```

- `FHOPS_REM`: the flood hops remaining. A packet whose `FHOPS_REM` is zero is
  not flood-forwarded.
- `FHOPS_ACC`: the flood hops accumulated. A sender sets it to zero.

Each repeater that flood-forwards a packet decrements `FHOPS_REM` and
increments `FHOPS_ACC`, as [UEP-0014](uep-0014.md) defines, so the two
usually sum to the limit the sender set. A packet floods for at most 15 flood
hops.

A packet without `FHOPS` is not flood-forwarded. `FHOPS` and the `H` bit are
not covered by the MIC, so `FHOPS` changes in transit without invalidating a
packet.

## Security Information {#secinfo}

```text
+-----+---------------+----------+
| SCF | FRAME COUNTER |  [SALT]  |
+-----+---------------+----------+
  1 B        4 B         0/2 B
```

### Security Control Field {#scf}

```text
  7   6   5   4   3   2   1   0
+---+-------+---+---+-----------+
| E |  MIC  | S | D | RESERVED  |
+---+-------+---+---+-----------+
 1b  2 bits  1b  1b    3 bits
```

- `E`: set when the packet is encrypted.
- `MIC`: the length of the packet's MIC:

  | Value | MIC length |
  |---:|---|
  | 0 | 4 bytes |
  | 1 | 8 bytes |
  | 2 | 12 bytes |
  | 3 | 16 bytes |

- `S`: set when `SALT` is present.
- `D`: set when `SIG` is present.
- `RESERVED`: a sender sets these bits to 0, and a receiver discards a packet
  that has any of them set.

### Frame Counter {#frame-counter}

A 4-byte unsigned integer that orders the source's packets.
[UEP-0007](uep-0007.md) defines how a sender advances it and how a receiver
judges it.

### Salt {#salt}

Two random bytes that a sender may add to vary a packet's security inputs, as
[UEP-0007](uep-0007.md) defines.

## Layouts {#layouts}

### Broadcast {#broadcast}

A broadcast is addressed to every node that receives it. It carries no
SECINFO and no MIC, and is neither encrypted nor authenticated by a MIC.

```text
+-----+-------+--------+---------+-----------+
| FCF |[FHOPS]|  SRC   | OPTIONS | [PAYLOAD] |
+-----+-------+--------+---------+-----------+
  1 B   0/1 B  3/32 B   variable   variable
```

### MAC Ack {#mac-ack}

A MAC ack acknowledges a packet that requested one. It carries no destination
and no source, and ends in an 8-byte ack trailer:

```text
+-----+-------+---------+---------+---------+
| FCF |[FHOPS]| OPTIONS | ACK MIC | ACK TAG |
+-----+-------+---------+---------+---------+
  1 B   0/1 B  variable     4 B       4 B
```

- `ACK MIC`: the first 4 bytes of the acknowledged packet's MIC.
- `ACK TAG`: a 4-byte tag that authenticates the ack to the acknowledged
  packet's sender, as [UEP-0007](uep-0007.md) defines.

A MAC ack carries no payload. A sender MUST NOT place bytes between an end
marker and the ack trailer, and a receiver discards an ack that has them.

### Unicast {#unicast}

A unicast is addressed to one node by its node hint. `UNIC` and `UNAR` share
one layout. `UNAR` asks the destination to answer with a MAC ack.

```text
+-----+-------+-----+--------+---------+---------+-----------+-------+--------+
| FCF |[FHOPS]| DST |  SRC   | SECINFO | OPTIONS | [PAYLOAD] | [SIG] |  MIC   |
+-----+-------+-----+--------+---------+---------+-----------+-------+--------+
  1 B   0/1 B   3 B  3/32 B   5/7 B    variable   variable   0/64 B  4–16 B
```

When `E` is set, `PAYLOAD` and `SIG` are encrypted.

### Multicast {#multicast}

A multicast is addressed to the members of a group. The source follows the
options, so the [end marker](uep-0003.md#end-marker) is always present.

When `E` is set, the source is encrypted with the payload, so that only
members of the group learn who sent it:

```text
+-----+-------+-------+---------+---------+----+--------------------------------+--------+
| FCF |[FHOPS]| GROUP | SECINFO | OPTIONS | FF | ENCRYPT(SRC ‖ PAYLOAD ‖ [SIG]) |  MIC   |
+-----+-------+-------+---------+---------+----+--------------------------------+--------+
  1 B   0/1 B   2 B    5/7 B    variable   1 B     3/32 B + variable + 0/64     4–16 B
```

When `E` is clear, the same fields appear in the clear, in the same places:

```text
+-----+-------+-------+---------+---------+----+--------+-----------+-------+--------+
| FCF |[FHOPS]| GROUP | SECINFO | OPTIONS | FF |  SRC   | [PAYLOAD] | [SIG] |  MIC   |
+-----+-------+-------+---------+---------+----+--------+-----------+-------+--------+
  1 B   0/1 B   2 B    5/7 B    variable   1 B  3/32 B    variable   0/64 B  4–16 B
```

### Group Unicast {#group-unicast}

A group unicast is addressed to one node and carried in a group. Its payload
is secured with keys that require both the group key and the two endpoints'
pairwise keys. `GUNI` and `GUAR` share one layout. `GUAR` asks the destination to answer with a MAC ack.
As in multicast, the end marker is always present.

When `E` is set, the destination hint and source are encrypted together with
the group's key, and the payload with keys that only the two endpoints hold:

```text
+-----+-------+-------+---------+---------+----+-------------+-------------------------+--------+
| FCF |[FHOPS]| GROUP | SECINFO | OPTIONS | FF | ENC_DST_SRC | ENCRYPT(PAYLOAD ‖ [SIG]) |  MIC   |
+-----+-------+-------+---------+---------+----+-------------+-------------------------+--------+
  1 B   0/1 B   2 B    5/7 B    variable   1 B    6/35 B          variable + 0/64        4–16 B
```

`ENC_DST_SRC` is the encryption of `DST ‖ SRC`: a 3-byte node hint followed by
a source of 3 or 32 bytes, as `S` states.

When `E` is clear, the destination hint and source appear in the clear:

```text
+-----+-------+-------+---------+---------+----+-----+--------+-----------+-------+--------+
| FCF |[FHOPS]| GROUP | SECINFO | OPTIONS | FF | DST |  SRC   | [PAYLOAD] | [SIG] |  MIC   |
+-----+-------+-------+---------+---------+----+-----+--------+-----------+-------+--------+
  1 B   0/1 B   2 B    5/7 B    variable   1 B  3 B   3/32 B    variable   0/64 B  4–16 B
```

## Options {#options}

A packet's options are an [options block](uep-0003.md#options). A receiver
discards a packet whose options block is
[malformed](uep-0003.md#malformed), and a repeater does not forward it.

Each option's UEP defines its value and states how many times it may appear
in a packet.

### Locating the Options {#options-region}

A packet ends in a trailer whose length the receiver knows before reading the
options:

| Packet | Trailer length |
|---|---|
| Broadcast | 0 |
| MAC ack | 8 |
| Any other | The MIC length, plus 64 when `D` is set |

The options block begins after the fields that precede it, and the trailer
bounds it. A receiver reads option records up to the trailer. If it meets an
end marker, the bytes between the marker and the trailer are what the layout
places after the options. If it reaches the trailer without meeting one,
nothing follows the options.

### Option Attributes {#option-attributes}

The low four bits of an option's number state its attributes, so a node knows
how to treat an option it does not recognize:

- **Bit 0** set: forwarding-critical.
- **Bit 1** set: dynamic. Clear: static.
- **Low four bits 12 or 13**: delivery-critical.

| Low four bits | Attributes |
|---:|---|
| 0, 4, 8 | Static |
| 1, 5, 9 | Forwarding-critical, static |
| 2, 6, 10, 14 | Dynamic |
| 3, 7, 11, 15 | Forwarding-critical, dynamic |
| 12 | Delivery-critical, static |
| 13 | Forwarding-critical, delivery-critical, static |

Only a static option can be delivery-critical: a demand the sender makes of
the destination is one the MIC must protect.

### Criticality {#criticality}

A node that does not recognize an option treats it according to its
attributes:

- **Forwarding-critical**: a repeater does not forward the packet. The node
  may still accept the packet as its destination.
- **Delivery-critical**: a destination does not accept, deliver, or
  acknowledge the packet, and counts the discard. A repeater forwards it as
  usual.
- **Neither**: the node ignores the option.

A node that both forwards and accepts a packet applies each rule to its own
role. A node that recognizes an option but cannot interpret its value, such
as a value of the wrong length, treats the option as unrecognized.

A MAC ack delivers nothing, so a receiver accepts an otherwise valid ack
whatever delivery-critical options it carries.

### Dynamic and Static Options {#dynamic-static}

- A **static** option is covered by the packet's MIC and frame signature, and
  a forwarder MUST NOT change it.
- A **dynamic** option is not covered by the MIC, and a forwarder may add,
  change, or remove it as the option's UEP allows.

Dynamic options carry what changes along a packet's path, such as a
[source route](uep-0015.md) or a [trace](uep-0016.md#trace).

## Payload {#payload}

A payload is empty, or begins with a **payload type** that names the protocol
carried in the rest of it. The payload type is a
[packed unsigned integer](uep-0003.md#pui), so a payload type from 0 to 127
takes one byte. A receiver discards a packet whose payload type is malformed.
The MAC layer delivers a payload to the protocol its payload type names
without interpreting it.

### Packet Type Compatibility {#compatibility}

The UEP that allocates a payload type states which packet types may carry it.
For this purpose, group unicast counts as unicast. A receiver discards a
packet whose payload type its packet type may not carry.

Any packet type that carries a payload may carry an empty one, or one of
payload type 0, **Unspecified**, whose content has no declared protocol.

### Response Carriage {#response-carriage}

A response to a unicast request is carried the way the request was: a request
that arrived as group unicast on a group is answered as group unicast on that
group, and a request that arrived as unicast is answered as unicast. This
holds for every request and response, whether the MAC layer or a protocol
above it answers.

A response sent outside the group would name the endpoints that the request
concealed. A MAC ack is not a response: it names neither endpoint.

A response to a multicast or broadcast request is not bound by this rule. The
request's UEP states how it may be answered.

## Registry Considerations {#registry-considerations}

This UEP creates three registries: [Packet Types](registries/packet-types.md),
[Packet Options](registries/packet-options.md), and
[Payload Types](registries/payload-types.md).

### Packet Types {#packet-types-registry}

Values 0 to 7, allocated by a standards UEP. The registry reserves no
experimental values. Initial contents are the table in
[Packet Types](#packet-types), with value 5 reserved.

### Packet Options {#packet-options-registry}

Values 0 to 65535, allocated by a standards UEP. An option's number MUST have
the [attributes](#option-attributes) its definition gives it.

Values from 60000 up are
[experimental](uep-0001.md#experimental-values). They cost the most to
encode, and contain values of every attribute combination.

This UEP allocates no options.

### Payload Types {#payload-types-registry}

Values 0 to 2,097,151, allocated by a standards UEP whose definition states
the packet types that may carry the value. A value from 0 to 127 takes one
byte, and is allocated only to a payload type carried often enough that the
byte matters.

Values from 60000 up are
[experimental](uep-0001.md#experimental-values).

This UEP allocates:

| Value | Name | Defined in |
|---:|---|---|
| 0 | Unspecified | [UEP-0005](#compatibility) |
| 1 | Node Identity | [UEP-0011](uep-0011.md) |
| 2 | MAC Command | [UEP-0006](uep-0006.md) |
| 3 | Text Message | [UEP-0020](uep-0020.md) |

## Security Considerations {#security-considerations}

The MIC does not cover `FHOPS`, the FCF's `H` bit, or dynamic options. Any
node in radio range can change them, which affects how a packet is forwarded
but not what its destination accepts. A behavior that a destination relies on
belongs in a static option.

A broadcast carries no MIC, so nothing in a broadcast is authenticated except
by a frame signature in an option, as [UEP-0007](uep-0007.md) defines.

Fields outside the encryption reveal traffic metadata:

- A unicast reveals its destination hint and its source hint or address.
- A multicast reveals its group hint. When encrypted, it conceals its
  source from nodes outside the group.
- A group unicast reveals its group hint. When encrypted, it conceals
  both endpoints from nodes outside the group.
- A MAC ack names neither endpoint, but correlates with the packet it
  acknowledges through `ACK MIC`.
- Every packet reveals its type, its length, and its options, and a packet
  that carries SECINFO reveals its frame counter.

A receiver parses every field from untrusted input. It bounds each length by
the bytes that remain before the trailer, and discards a packet whose fields
do not fit.
