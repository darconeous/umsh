This UEP defines groups: what a group key grants, how a node obtains one, and
what group traffic does and does not prove about its sender.

## Groups {#groups}

A **group** is defined by a 32-byte symmetric **group key**. Holding the key
is what makes a node a member, and nothing else is needed. A group serves two
purposes:

- **Multicast**: every member can send and receive
  [multicast](uep-0005.md#multicast) packets in the group.
- **Group unicast**: a member can send a
  [group unicast](uep-0005.md#group-unicast) to another member, secured with
  keys that only the two of them hold. When encrypted, its payload is
  readable only by its destination, and its source and destination are
  concealed from nodes outside the group.

From the group key, every member derives the group's packet keys, its
[group ID](uep-0007.md#group-id), and its
[group hint](uep-0007.md#group-hint), as [UEP-0007](uep-0007.md) defines.
The group ID names a group to a local interface or another node without
disclosing its key.

A member chooses per packet whether to encrypt group traffic. An unencrypted
multicast is still authenticated, and suits operation where encryption is not
permitted, such as [amateur radio operation](uep-0017.md#originated).

## Named Groups {#named-groups}

A **named group** derives its key from a name, so anyone who knows the name
can join. A named group offers no secrecy. A long, high-entropy name gives
only obscurity.

The name is canonicalized and the key derived from it:

1. The name MUST consist only of ASCII characters. A node rejects any other
   name.
2. ASCII letters `A` to `Z` are folded to `a` to `z`. No other character
   changes.
3. The group key is

   ```text
   group key = HKDF-Extract-SHA256(salt = "UMSH-CHANNEL-V1", ikm = canonical name)
   ```

So `Public`, `public`, and `PUBLIC` name the same group. The name is not a
secret, so the derivation is a plain HKDF-Extract
([RFC 5869](https://www.rfc-editor.org/rfc/rfc5869)), not a password-based
function.

## Simple Private Groups {#simple-private-groups}

A **simple private group** has a random group key, which its members share
by any secure means: a URI or QR code ([UEP-0019](uep-0019.md)), or a unicast
between members. There is no authority over a simple private group. A member
cannot be removed except by moving the remaining members to a new key.

## Sender Attribution {#sender-attribution}

A multicast's MIC shows only that its sender holds the group key. Any member
can send a multicast that names any source, and no other member can tell from
the MIC who sent it.

A signed multicast is the exception. Its
[frame signature](uep-0007.md#frame-signatures) attributes it to the key that
signed it, and covers the group ID, so it cannot be moved to another group
that shares its group hint. A signature costs 64 bytes, and a receiver can
check it only against an address it holds or that the packet carries in full.
A multicast whose signature does not verify is attributed to no one.

A group unicast's payload is secured with keys that also require the
pairwise keys of its two endpoints, so it is attributed to its source.

## Group Traffic {#group-traffic}

Group traffic identifies its payloads by the same
[payload types](uep-0005.md#payload) as other traffic. A payload type defined
for unicast is not thereby defined for multicast: its UEP states whether
multicast may carry it, and what it means there. A receiver discards a
multicast whose payload type is not permitted on multicast, as
[UEP-0005](uep-0005.md#compatibility) defines. A MAC command, for example, is
carried by multicast only when its definition permits it, which Echo's does
not. A group unicast may carry whatever a unicast may.

A node MUST NOT answer a request carried by multicast unless the request's
UEP defines how a multicast request is answered.

Group traffic reaches beyond a single hop by being
[forwarded](uep-0013.md), like any other traffic.

## Security Considerations {#security-considerations}

A multicast request reaches every member at once, and any member can send
one. A node that answered it as it would a unicast request would let one
packet draw a response from every member in range, each flooded back across
the mesh, and would answer a sender that may not be who its `SRC` claims. A
node therefore answers a multicast request only as the request's UEP defines
for multicast, and ignores it otherwise.

A named group is public. Anyone who knows or guesses its name can read its
encrypted traffic and send to it.

Every member of a group can read its encrypted multicast, read the address
block of its group unicast, and send an unsigned multicast that names any
other member as its source.

A member keeps the key it holds. Removing a member takes a new key, which
changes the group's hint and ID.

A group hint is two bytes, so unrelated groups share one. A node holding
several keys with the same hint tries each, and only the right one verifies
a packet's MIC. A shared hint costs computation, never misdelivery.

A group's hint is visible on every packet in the group, so an observer can
tell when packets belong to the same group, but not which group it is unless
the observer can derive the key, as for a named group.
